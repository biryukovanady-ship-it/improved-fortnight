# Трекер удалённых вакансий

Здесь ведём поиск постоянной удалённой работы экономиста и финансового аналитика: проверяем вакансии, фиксируем отклики и следующие шаги.

## Быстрый старт

1. Откройте [таблицу вакансий](tracker/vacancies.csv). Она пока содержит только заголовки. Правила заполнения и импорт в Excel описаны в [инструкции к таблице](tracker/README.md).
2. Для новой позиции создайте issue через [New issue](https://github.com/biryukovanady-ship-it/improved-fortnight/issues/new/choose), выбрав форму **Новая вакансия**.
3. Присвойте записи ID вида `VAC-0001`. Укажите его в таблице и заголовках всех связанных issues. Номер issue и ID вакансии могут различаться.
4. Для подготовки или отправки отклика используйте форму **Отклик**, а для каждого этапа интервью форму **Этап собеседования**. Свяжите их с основной карточкой вакансии.
5. После каждого события обновляйте строку таблицы: статус, следующее действие и срок. Issues и CSV обновляются вручную.

Шаблоны становятся доступны в New issue после попадания файлов в основную ветку `main`.

## Что ищем

- Постоянная удалённая работа с возможностью работать из России. График 5/2 подходит.
- Направления: экономика, финансовая аналитика, бюджетирование, управленческий учёт, себестоимость и анализ продаж.
- Основной источник: карьерные страницы работодателей. Если работодатель ведёт отклики через внешнюю площадку, сохраняйте также ссылку на его карьерную страницу в комментарии.
- Приоритет крупным компаниям от 300 сотрудников: ИТ, сырьевой сектор, производство, включая мебельные фабрики. Численность подтверждайте источником. Для исключений указывайте причину.
- В свежую подборку входят вакансии, опубликованные не более 21 календарного дня назад на дату составления подборки. Дата обнаружения или проверки не заменяет дату публикации. Обновление страницы само по себе не подтверждает новую публикацию.
- Вакансии без даты можно сохранить для проверки, но нельзя представлять их как подтверждённо свежие.
- Требование свободного разговорного английского не подходит текущему поиску. Возможность переписки с помощью ИИ проверяем по конкретным обязанностям. Если язык не указан, ставим «Не указано».
- Командировки и обязательные посещения офиса проверяем отдельно. Предпочтение работе без командировок.
- Зарплату и её налоговую базу записываем по объявлению. Числовой минимум желаемой зарплаты пока не задан.

## Правила ведения

**Одна позиция, одна строка и одна основная карточка.** Перед добавлением проверьте таблицу, открытые и закрытые issues по URL, работодателю и названию позиции. Копия объявления на другом сайте не создаёт новую вакансию. Повторную публикацию отмечайте в существующей карточке; отдельный ID нужен для другого набора или другой позиции.

**Каждый факт должен иметь источник.** Сохраняйте прямую ссылку на объявление и дату проверки. Дату публикации, удалёнку, численность и зарплату не восстанавливайте по догадке. Неизвестные числа и даты оставляйте пустыми, а вопрос записывайте в комментарии. Неизвестное значение не равно нулю.

**Соответствие и статус решают разные задачи.** Соответствие показывает, подходит ли работа. Статус показывает, на каком шаге находится процесс. Используйте значения «Подходит», «Требует уточнения» и «Не подходит» для соответствия; причины указывайте в комментарии. Приоритет: «Высокий», «Средний» или «Низкий». Высокий приоритет требует краткого объяснения.

**История остаётся в issues.** В основной карточке держите актуальные условия и ссылки на отклик и интервью. В комментариях фиксируйте дату, событие, результат и следующий шаг. Для одного отклика ведите одну карточку от подготовки до результата. Для каждой встречи или тестового задания создавайте отдельную карточку этапа.

**Отправленный отклик должен быть подтверждён.** Статус «Отклик отправлен» и дату отклика ставьте после фактической отправки. Сохраните краткое подтверждение, например номер заявки. Подготовка письма или создание issue отправкой не считаются.

**У каждой активной записи есть следующий шаг.** Записывайте конкретное действие и срок. Ожидание ответа также требует даты следующей проверки. Перед откликом повторно проверьте доступность объявления и условия. Отсутствие ответа не означает отказ.

**Завершённые записи не удаляем.** При отказе, закрытии вакансии или принятии оффера обновите статус, запишите дату и причину в issue, затем закройте связанные карточки. Закрытые issues остаются частью истории. Карточку этапа можно закрыть после завершения встречи, оставив вакансию открытой.

Репозиторий публичный. Резюме, личные контакты, переписку и закрытые материалы тестовых заданий храните вне него. Здесь достаточно версии документа и краткого обезличенного результата.

## Статусы таблицы

| Статус | Когда использовать |
| --- | --- |
| Найдена | Позиция добавлена, первичная проверка впереди. |
| Проверяется | Уточняем дату, условия или соответствие. |
| К отклику | Проверка закончена, решение откликнуться принято. |
| Подготовка отклика | Готовим резюме и сопроводительное письмо. |
| Отклик отправлен | Отправка подтверждена, ждём первого ответа. |
| Собеседование | Запланирован или идёт этап интервью. |
| Тестовое задание | Получено задание, готовим или сдаём результат. |
| Ожидаю решение | Текущий этап завершён, ждём решения работодателя. |
| Оффер | Предложение получено, решение ещё не принято. |
| Принят оффер | Предложение принято; процесс завершён. |
| Отказ работодателя | Получен явный отказ; процесс завершён. |
| Отказ кандидата | Решено прекратить участие; процесс завершён. |
| Вакансия закрыта | Закрытие подтверждено источником; процесс завершён. |
| Не подходит | Проверка выявила неподходящие условия; процесс завершён. |

Для завершённых записей следующее действие и срок можно оставить пустыми.

## Как менять и отменять

Структуру и правила удобно менять в отдельной ветке с pull request. Никакой автоматической отправки откликов или изменения статусов здесь нет.

До слияния изменений достаточно закрыть pull request. После слияния добавление или правку файлов можно отменить через Revert в GitHub либо отдельный коммит `git revert`. Ошибочно закрытый issue можно открыть снова. Историю репозитория не переписываем.
